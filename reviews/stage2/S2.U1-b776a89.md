## Review
Standards: small ES modules; all user text goes through `textContent` (`dom.js h()`), so names and notes cannot inject markup;
one error slot (`auth-error`, `role=alert`) that exists only while there is an error and is cleared on input; a fetch wrapper
that treats 5xx, timeouts and unparseable bodies as "unknown", never as a refusal; the token lives in localStorage and is cleared on
401 or Log out. No inline scripts (CSP-compatible).
Spec: every testid in the Signup and login table is present with the stated semantics. `current-handle`'s text is exactly the handle
(the "@" is drawn by CSS), and `current-user` is visible on every signed-in route at all three widths. Guarded redirects work.
Notes (non-blocking):
- Long display names are truncated with an ellipsis in the header (the full text stays in `current-user`'s textContent). Consider a
  `title` attribute.
- The header chip shows "1234567890.12 EUR" with no digit grouping. That is the spec's exact format for the testids, but grouping in non-testid
  places would read better.
- The logout button carries an inline `style` (allowed by the CSP's style-src 'unsafe-inline'); move it into components.css.
