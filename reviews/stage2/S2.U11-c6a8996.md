## Findings

**F5 — "A refused payment shows `pay-error` …"; Product direction: "refused … states must be visually distinct".**
With the slot now below the button, a refusal on the wallet's Send form at a common phone viewport, **390 × 844**, is rendered entirely
**underneath the fixed bottom tab bar**. The message box spans y 799–844 and the tab bar starts at y 784, so 0 px of it is visible. The user sees
nothing happen. `showError`'s `scrollIntoView({block: "nearest"})` treats the element as already in view because it ignores the fixed bar.
Screenshot of the real viewport: `reviews/stage2/shots/U11-c6a8996-u3/390x844-pay-error-under-tabbar.png` (the form, then the tab bar,
and no error). DOM-level checks (walker, Playwright `is_visible`, analyst tests) cannot see this, because the element is "visible".
Repro: `$PY reviews/stage2/tools/feedback_cover.py http://127.0.0.1:<port>` → `390 pay {... 'hidden_px': 60, 'fully_hidden': True}`.
At other sizes (375×667, 768×1024, 1280×800) and for request, authorize and request-row pay it happened to land in view, but whether it does
depends on scroll position, so any form near the bottom of a ≤ 999 px viewport is exposed.
Expected: refusal and uncertainty feedback is visible above the tab bar. For example, `scroll-padding-bottom`/`scroll-margin-bottom` equal to the
tab-bar height, so that `scrollIntoView` clears it.
